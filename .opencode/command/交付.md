## 第 1 步：硬校验（不通过就停）
在 `<AI_FACTORY_ROOT>` 下运行：

```
python ops\bus\check_handoff.py
```

退出码非 0 → 直接报 FAIL，列出每条 `FAIL ...`，**不得**输出 PASS，也不得手改回执来“修绿”。

## 第 2 步：证据检查（逐张回执）
读取 `ops/bus/out/T*.json`，对每张卡核对：
1. 必备字段：`task_id` / `owner` / `status` / `artifact` / `sha` / `rows`。
2. `status` 只能是 `PASS` / `FAIL` / `UNVERIFIED`；`PASS` 才允许进入交付。
3. `artifact` 必须存在；`sha` 与文件 sha256 前 16 位一致。
4. `rows` 必须 > 0，且与回执里说的检查项数量对得上。
5. 有 `evidence_path` / `report.path` 的，路径必须存在。
6. `state.json` 的 owner 与回执 owner 一致；同一 owner 不得占两个任务。
缺任何一项 → 该卡记 FAIL，写清缺什么；不要用推测补字段。

## 第 3 步：只输出三行凭证
格式固定，不要加第四行：

改了什么：<本窗口新增/修改的文件；纯验收写“无文件改动，仅验收”>
跑了什么：`python ops\bus\check_handoff.py` → exit <码>；证据检查 <通过数>/<总数> PASS
产物 sha：<主产物绝对路径> <sha256 前 16 位；没有写“无”>

若失败，第二行写实际失败项，第三行写 `未交付`。禁止把“跑了”写成“成了”。
