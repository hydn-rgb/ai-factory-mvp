主题 =「$ARGUMENTS」（可能为空）。

## 第 0 步：无参数先点选，不许猜
如果主题为空、只有空白，或只有“调研”两个字：**先调用 `question` 工具**，只问一个问题。

- header：`调研深度`
- question：`这次调研要做到什么深度？`
- options：正好 3 个，按下面顺序原样给出
  1. `轻 · 15 分钟` — 3–5 个 A/B 级来源，一页结论，不做红蓝对抗。
  2. `中 · 1 小时` — 6–10 个来源交叉验证，事实/推断/猜想分层，附可推翻条件。
  3. `重 · 3 小时` — 多源交叉 + 反方观点 + 红蓝对抗 + 证据链审计，产出决策备忘。

等用户点选后再继续。用户没选，就不执行调研，也不替用户默认选“中”。

## 第 1 步：按用户点选的级别执行
- **轻**：加载 `skill` 工具中的 `adler-reading-sop`。只做检视阅读：谁在说、说了什么、证据在哪、缺什么。
- **中**：加载 `systematic-intel-engine`。按「假设 → 证据 → 交叉验证 → 结论」四段做，至少两个独立来源。
- **重**：依次加载 `systematic-intel-engine`、`red-blue-due-diligence`、`evidence-chain-auditor`。蓝军先出结论，红军专挑反例，证据链审计官最后判定哪些结论能进决策。

## 证据规则（所有级别都适用）
- 每个关键数字都要带：来源 URL、来源级别 A/B/C/D、抓取时间。
- 事实 / 推断 / 猜想必须分开写；不确定标 `UNVERIFIED`，禁止编造。
- 不付费调用；不碰内部数据；不把“听说”写成事实；不硬编码任何 key。

## 结尾（必须有，只写这三行）
改了什么：<本次新增/修改的文件；没有就写“无文件改动，仅输出结论”>
跑了什么：<实际执行的工具/命令 + 退出码；没有就写“无”>
产物 sha：<产物绝对路径 + sha256 前 16 位；没有产物写“无”>
