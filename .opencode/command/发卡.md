目标 =「$ARGUMENTS」。

如果为空：先用 `question` 工具问一次「这张卡要解决什么？」，给 3 个可点选项（`情报调研` / `工程交付` / `验收自动化`），等用户选完再继续；不要自己编目标。

## 步骤
1. 读 `ops/bus/state.json`、`ops/bus/README.md`，再读一张现有卡（如 `ops/bus/tasks/T5.md`）对齐格式。
2. 取现有最大 T 号 + 1 作为新卡号（如 T10），owner 同步为 `W10`；已存在同名卡就停，不覆盖。
3. 写前备份：`state.json` → `state.json.bak-<yyyyMMdd-HHmmss>`；记录当前 mtime/sha，写完前再核一次，变了就停。
4. 生成 `ops/bus/tasks/T<n>.md`，**不超过 20 行**，字段齐全：
   `task_id / owner / parent / 目标 / 输入 / 输出 / 验收 / 预算 / 禁止 / 回执`
   - 验收必须可执行、可证伪；预算默认 `¥10 / 2h`。
   - 禁止默认：不装第三方依赖；不改宪法/审批；不硬编码 key。
5. 登记 `state.json`：`owner=W<n>`、`status=todo`、`artifact=""`、`sha=""`；只增改这一条，不动别人。
6. 写后校验 JSON 可解析；输出：新卡路径、卡行数、state diff、备份路径。

## 禁止
不覆盖已有卡；不替人做价值判断；不一次性发多张；不在卡里写密钥或内部数据。
